## Първа задача за Claude: 500 без вход и без Accept

В работещия API:

```bash
curl -s -o /dev/null -w '%{http_code}\n' -H 'Accept:' http://localhost:8080/api/v1/me
# действително 500; очаквано 401
curl -s -o /dev/null -w '%{http_code}\n' -H 'Accept: application/json' http://localhost:8080/api/v1/me
# действително 401
```

При първата заявка отговорът е `Route [login] not defined.` (`RouteNotFoundException`). Причината е проверена по кода: framework `Authenticate::unauthenticated` извиква redirect callback, когато `expectsJson()` е false; callback в `ApplicationBuilder` търси route `login`, която API няма. Това се случва преди съществуващият `shouldRenderJsonWhen` в `bootstrap/app.php` да обработи нормален `AuthenticationException`. Само този callback за формата на грешката не поправя проблема.

Обичайният web клиент изпраща Accept JSON и работи. Не е установено изтичане на потребителски записи. Дефектът не е внесен от UX PR-ите: последната промяна на bootstrap/app.php е `5d65473`, преди тях, и работещият контейнер съвпада с main. Нужен е отделен PR: regression тест с обикновен GET без Accept (не само getJson), поправка на API auth/redirect поведението, проверка че JSON отказите и нормалните сесии/CSRF се запазват. Прилага се процесът за промяна около auth; не се заобикаля защитата и не се добавя фиктивна страница за вход само за прикриване на проблема.
