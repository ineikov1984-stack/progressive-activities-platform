## Следващи стъпки по сигурността (открити при работа по proxy-то)

- **IP на клиента към API-то** (строга) — сега API-то вижда IP-то на web контейнера за всички заявки, затова ограничението за опити за вход е практически само по имейл. Освен това лимитът (5 в минута) брои и успешните входове: e2e тестът го удари при 6-и вход. Да се броят само неуспешните опити и лимитът да се нулира при успех. Нужно е: web proxy-то да подава реалния IP (от доверения load balancer), а Laravel да вярва само на web контейнера (`trustProxies`). *Claude.*
- **Сесия: защита при смяна на парола** — преди да има смяна или възстановяване на парола, включи `AuthenticateSession` (прекратява другите сесии) + тест. Без това смяна/възстановяване на парола не се пуска (строга). *Claude.*
- **Сесия: едновременни заявки** — записът на сесията е „последният печели“; заявка в движение може да върне по-стара версия (напр. избраната организация). Web приложението не разчита на организацията в сесията (праща `X-Organization-Id`); да не се добавя нищо важно в сесията без session blocking (стандартна). *Claude.*
- **Сесия: максимален живот** за администратор и финанси преди пилота (сега сесията се подновява при активност без горна граница) — решение + настройка (строга). *Claude.*
- **API: 500 вместо 401 без `Accept: application/json`** (бърза) — Laravel търси несъществуващ маршрут `login`; да връща JSON 401 за всички `api/*`. *Codex.*
- **Бавен web в Docker (1–12 s на заявка)** (стандартна) — `next dev --webpack` в контейнер без mount; да се измери и да се избере по-бърз режим за локална работа. *Claude.*
- **CSP с nonce** (стандартна) — да се махне `'unsafe-inline'` за скриптове чрез nonce за всяка заявка. *Claude.*
