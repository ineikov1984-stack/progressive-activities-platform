## Следващи стъпки по сигурността (открити при работа по proxy-то)

- **IP на клиента към API-то** (строга) — сега API-то вижда IP-то на web контейнера за всички заявки, затова ограничението за опити за вход е практически само по имейл. Освен това лимитът (5 в минута) брои и успешните входове: e2e тестът го удари при 6-и вход. Да се броят само неуспешните опити и лимитът да се нулира при успех. Нужно е: web proxy-то да подава реалния IP (от доверения load balancer), а Laravel да вярва само на web контейнера (`trustProxies`). *Codex.*
- **Сесията не запазва записи от API-то** (строга) — `POST /api/v1/context/organization` връща 200, но следващата заявка пак няма `active_organization_id` (409). Вероятно същата причина като при подновяването на сесията. Докато се изясни, web-ът изпраща организацията със заглавка и за снимките. *Codex разследва, Claude review.*
- **Подновяване на сесията** (строга) — да се изясни защо бисквитката от не-входни отговори разваля сесията и да се направи безопасно подновяване. Вероятно е свързано с предишната точка; Codex разследва заедно, Claude прави web частта. *Codex + Claude.*
- **API: 500 вместо 401 без `Accept: application/json`** (бърза) — Laravel търси несъществуващ маршрут `login`; да връща JSON 401 за всички `api/*`. *Codex.*
- **Бавен web в Docker (1–12 s на заявка)** (стандартна) — `next dev --webpack` в контейнер без mount; да се измери и да се избере по-бърз режим за локална работа. *Claude.*
- **CSP с nonce** (стандартна) — да се махне `'unsafe-inline'` за скриптове чрез nonce за всяка заявка. *Claude.*
