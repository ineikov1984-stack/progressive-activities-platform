## Следващи стъпки по сигурността (открити при работа по proxy-то)

- **IP на клиента към API-то** (строга) — сега API-то вижда IP-то на web контейнера за всички заявки, затова ограничението за опити за вход е практически само по имейл. Нужно е: web proxy-то да подава реалния IP (от доверения load balancer), а Laravel да вярва само на web контейнера (`trustProxies`). *Codex.*
- **Подновяване на сесията + e2e тест за истински вход през proxy-то** (строга) — да се изясни защо бисквитката от не-входни отговори разваля сесията и да се направи безопасно подновяване. Тестът трябва да влиза в CI, за да не се повтори 29.10.2026. *Claude.*
- **API: 500 вместо 401 без `Accept: application/json`** (бърза) — Laravel търси несъществуващ маршрут `login`; да връща JSON 401 за всички `api/*`. *Codex.*
- **Бавен web в Docker (1–12 s на заявка)** (стандартна) — `next dev --webpack` в контейнер без mount; да се измери и да се избере по-бърз режим за локална работа. *Claude.*
- **CSP с nonce** (стандартна) — да се махне `'unsafe-inline'` за скриптове чрез nonce за всяка заявка. *Claude.*
