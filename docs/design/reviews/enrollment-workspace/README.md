# Записвания и избрана група — реализация на одобрения UX

Основа: одобреният `docs/design/mockups/MobileWorkspace.html` (#148). Продължава началното табло и мобилното меню (#149). Клон: `codex/enrollment-workspace`.

## Направено

- Ясно откроени „Заявки / Чакащи / Групи“, същите решения и филтри за заявките.
- Директни карти на групите с дейност, график, място и наличните бройки; търсене по дейност/група/място, филтър за дейност и запазените филтри за свободни/пълни/с чакащи. Допълнителните филтри са прибрани на телефон.
- Една избрана група: постоянен избор на телефон, страничен списък на широк екран и връзка към нейния график. Изборът и основният изглед са в адреса, така че презареждане и „Назад“ работят. Търсенето в групите се запазва при връщане от избрана група.
- Деца, чакащи и настройки са отделени. Преместване, пауза, пропуск, прекратяване/отмяна, контактите и подробностите използват съществуващите компоненти и правила. Търсенето на дете се пази при отваряне/затваряне на подробностите; фокусът се връща към детето.
- Записаната настройка за одобрение се запазва при смяна на изгледите; след одобрена заявка се обновяват и вече заредените бройки на групите.
- Учителят запазва своя обхват; липсващите от API чакащи, настройки и места не се измислят. Правата, маршрутите и бизнес правилата са непроменени.

## Проверки

- 15 unit теста за представянето на записванията; TypeScript, ESLint и docs:check.
- 5 нови browser проверки: потокът на 390/768/1440, дете/фокус/запазено търсене, запазена настройка, връщане/адрес, собствен обхват, грешка/повторение и обновяване на бройките след решение.
- Съществуващите проверки на записванията/редактора на 360/390/768/1024/1440 са пуснати локално; окончателната проверка на приложението и реалното API е в CI.
- Независимо UX ревю върху компонентите и седемте снимки: 0 blocker, 0 should-fix на 390/768/1440; включително контекст при скрол на 390. Ревюърът не е писал кода и не е изпълнявал приложението.
- Снимките и локалните API граници използват само синтетични данни. Те не доказват реални писма, RLS или конкурентност; тези правила са в съществуващото API и неговите проверки.
